# CSS-гайдлайн проекта SoftSnow

## 1. Назначение и принципы
Единый источник истины для стилей — четыре CSS-файла в `css/`. Визуальный дизайн
(значения, пропорции) берётся из Figma; структура реализации — из существующей
архитектуры кода. Приоритет при любых правках: **стабильность > чистота > красота**.
Не ломай текущий визуальный результат ради переименования или «идеальной» структуры.

## 2. Обязательные правила
- Все цвета, размеры шрифтов, радиусы, отступы, тени, transition и z-index —
  **только через CSS-переменные** из `tokens.css` (кроме локальных, сугубо
  секционных значений, которые не повторяются).
- Используй наследование и каскад: не дублируй значения, уже заданные родителю.
- **Не дублируй** компоненты и классы. Один элемент = один источник определения.
- При правке сохраняй вёрстку 1:1 с макетом; проверяй в браузере.
- Перед созданием нового класса проверь `FIGMA.md` и существующие компоненты.

## 3. Структура файлов
Подключаются в `index.html` и страницах в этом порядке (поздний файл побеждает при
равной специфичности):
1. `tokens.css` — **только** `:root` с переменными. Никаких правил селекторов.
2. `utilities.css` — reset (`*`), `body`, типографика (`h1–h6`, `p`), `img`, `a`,
   `ul/ol`, `button`, `input`, `::selection`, `:focus-visible`, глобальный
   `section { overflow: hidden }` и блок `prefers-reduced-motion`.
3. `components.css` — переиспользуемые UI-паттерны: `.container`, `.card*`,
   `.btn` + модификаторы (`.btn--primary/outline/ghost/search/md/lg`), `.carousel-nav*`,
   `.tabs*`.
4. `sections.css` — layout и контент конкретных секций (`.header`, `.hero`, …,
   `.footer`), а также привязанные к разметке блоки `.dropdown`, `.breadcrumb`,
   `.logo` (шапка). Компоненты, тесно связанные с разметкой страницы, остаются здесь.

## 4. Именование классов
- БЭМ: `block__element--modifier`. Не называй классы по визуалу (`blue-button`).
  Figma «Large title» → `.section-title`, «Blue Button» → `.btn--primary`.
- Визуальный вариант Figma = модификатор существующего компонента, а не новый класс.
- Секционные классы (`hero`, `tasks`, `projects`) — норма; плохо только дублирование
  компонентов внутри них.

## 5. Токены
Объявляются в `:root` (`tokens.css`), сгруппированы по смыслу: цвета, фоны, градиенты,
шрифты, шкала типографики (`--fs-*`), `--control-h`, отступы (`--gap-*`, `--section-*`),
радиусы (`--radius-*`), границы, прозрачности, тени, transition (`--transition-fast/
base/slow`), z-index (`--z-header`, `--z-popover`).
Правила добавления:
- Не создавай токен для одной секции (например, `--hero-padding-37`).
- Не дублируй значение, уже существующее под другим именем (`--btn-16` удалён —
  дублирует `--fs-body-16`).
- Новый токен только если значение встречается в нескольких местах/Figma-фреймах.

## 6. Компоненты и секции
- **Компонент** — переиспользуемый паттерн на нескольких страницах (`.btn`, `.card`,
  `.container`, `.carousel-nav`, `.tabs`). Живёт в `components.css`.
- **Варианты `.btn`** (модификаторы в `components.css`): `.btn--primary` — залитая
  (brand sea), `.btn--outline` — с рамкой прозрачная, `.btn--ghost` — с рамкой
  прозрачная с sea-акцентом, `.btn--white` — белая, `.btn--black` — чёрная;
  `.btn--md` (262px) / `.btn--lg` (460px) — модификаторы ширины.
- **Секция** — layout конкретной части страницы; живёт в `sections.css`.
- Устаревший белый вариант `.btn--ghost` (в `components.css`) был мёртв — его
  перекрывал прозрачный вариант из `sections.css`. Единый живой `.btn--ghost`
  (прозрачный фон, 1px sea-бордер) теперь в `components.css`.
- Реестр актуальных компонентов ведётся в `FIGMA.md`.

## 7. Сетки и адаптивность
- Контентный контейнер: `.container` (max-width 1870px, padding 40px).
- Карточные сетки — CSS Grid с фиксированными колонками `repeat(N, 460px)` и
  `gap: 10px`; карточкам не нужен явный `width`, его задаёт колонка (удалено
  избыточное `width: 460px` в `.industries__card`, `.audience__card`, `.clients__card`).
- **Текущее состояние:** дизайн рассчитан на 1920px и **не содержит медиазапросов**.
  Ряд блоков имеет жёсткие фиксированные ширины (`1870px`, `890px`, `460px`,
  `242px`, `margin-left: 25px`), привязанные к макету.
- **Рекомендация:** добавить слой адаптива (breakpoints ~1440/1024/768/480),
  перевести фиксированные ширины на `justify-content`/`grid` 2-up и относительные
  единицы, не ломая 1920px-вид по умолчанию.

## 8. Псевдоклассы и состояния
- `:hover`, `:focus-visible`, `:disabled`, `.is-active`, `.is-open`, `.is-hidden`.
- Все transition — через токены: `--transition-fast` (0.2s), `--transition-base`
  (0.3s), `--transition-slow` (0.35s). Ключевое слово `ease` не пишется (дефолт).
- `.btn` приобрёл плавный `transform: translateY(-2px)` на hover.
- `--z-*` для слоёв (header 2, popover 20) — не пиши «голые» z-index.

## 9. Доступность
- `:focus-visible` с `outline: 2px solid var(--color-sea)` (в `utilities.css`).
- Семантические теги, `alt`, `aria-*` на интерактиве (например, dropdown).
- Контраст текста/фона соблюдать по WCAG AA.
- `prefers-reduced-motion` (в `utilities.css`) отключает анимации/transition
  через `!important` — это обоснованное a11y-переопределение пользовательской
  настройки ОС.

## 10. Чеклист ревью (перед коммитом)
- [ ] Нет новых `!important`, кроме a11y-переопределений (reduced-motion).
- [ ] Нет хардкод-значений, которые есть в токенах.
- [ ] Нет дублированных правил/классов.
- [ ] Новый класс не дублирует существующий компонент.
- [ ] Вёрстка проверена в браузере (1920px), визуал не изменился.
- [ ] Переменные не плодятся под одну секцию.
- [ ] `:focus-visible` и доступность сохранены.
